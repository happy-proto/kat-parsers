# 语法验证

新增、更新或修复 grammar／scanner 时读取。外部语料负责广泛发现缺陷，仓库内的精简回归负责长期防退化；二者都不能由生成成功或加载测试替代。

## 建立验证依据与范围

先确认目标语言版本和方言、权威实现及版本、语料仓库及 revision、调用入口。优先复用官方或事实标准实现的测试设施和预期结果；社区 Tree-sitter corpus 可作补充，不能单独证明语言覆盖。

按权威文法或实现梳理本次相关的结构与词法类别，再检查所选语料实际触及哪些类别。关注区分结构的边界、嵌套与组合，而非文件数或测试数。新增语言需覆盖主要语法类别；局部修复聚焦受影响类别及邻近规则；上游更新还需检查语法变化与原有本地修补。

没有官方测试集时，使用官方源码、示例及代表性真实项目，补充有依据的缺口样例。没有可运行的权威实现时，从可取得的正式文法、官方源码、示例或测试预期中选择替代依据，结合真实语料交叉验证；说明依据强度和未验证范围，不把下载失败、工具失败或未执行记录为通过。

## 运行可信的外部对照

- 完整语料和临时产物留在仓库外。关注独立源码、测试脚本中的内嵌字符串、模板和动态生成输入；提取时保留出处、预期结果、多文件依赖和必要上下文。记录无法提取或执行的部分，不称部分提取为完整上游测试。
- 优先使用官方语法检查或解析入口。用已知合法及非法输入确认工具实际处理目标内容，结合诊断区分解析、类型、依赖与运行期问题；dry-run 或非零退出码本身不是语法结论。会执行输入的工具应在临时工作目录运行，控制其副作用及超时。
- 明确比较对象：上游官方测试通过说明参考环境可用，还需将对应输入实际交给本仓库 parser。解析合法输入时检查 `ERROR` 和 `MISSING`；对关键结构核对节点类型、层级、字段、数量或字节范围，防止静默错分及文本吞并。
- 官方 AST 和 Tree-sitter AST 无需逐节点相同；比较的是语法接受范围与源码结构。Tree-sitter 不承担编译器全部语义校验。针对非法或不完整输入，验证终止、恢复及相邻合法结构的保留，不要求复刻官方诊断或所有拒绝行为。
- scanner 或上下文相关词法变化时，按风险验证状态边界与编辑后的增量解析；可将增量结果与同一最终输入的全新解析比较，检查树结构和范围一致。无需为无状态的局部规则变更机械增加整套增量测试。

## 判断差异

| 差异 | 处理 |
| --- | --- |
| 合法语法报错、缺节点、错分或边界错误 | 归类缺陷，提取回归并修复 grammar／scanner |
| 上游故意非法或不完整的输入 | 保留上游预期，检查本仓库的恢复契约；不强迫其无错解析 |
| 版本／方言不同、语料提取失真或缺少上下文 | 校正验证输入或环境后重跑，不直接修改 grammar 迎合错误前提 |
| 类型、字段校验、依赖或运行环境失败 | 不当作语法拒绝，改用解析证据或官方预期判断 |
| 原因未明 | 保留为待查并注明影响，不能通过删文件、改预期或静默跳过变成通过 |

按触发机制归组，而非逐文件修补。修复应解释为何符合权威语法及其词法上下文，避免为某个词、文件或样例添加特例；优先局部而完整地修正规则，检查邻近合法语法和已有结构契约。

## 把缺陷变成经济的回归

1. 从实际失败输入缩减出代表性样例，保留触发机制与必要上下文。缩减或组合会改变语义，需重新确认其语法有效性及来源依据；必要时用权威工具复核。
2. 在非生成测试路径持久化，并确认修复前版本能稳定失败。先证明断言检出目标问题，再修 grammar／scanner、重新生成、验证通过；新 parser 完成最小接入后也按此方式固定发现的缺口。
3. 断言针对故障的可观察结果。结构错误需检查节点或范围，不能只断言无报错；回归若本来针对合法输入报错，无 `ERROR`／`MISSING` 可直接作为该缺陷的断言。不快照整棵无关语法树来锁死实现细节。
4. 同一机制影响多个文件时保留代表性回归；不同机制和易互相掩盖的边界保留独立断言。相关语法及交互可以组合为少量元素丰富的样例，但要确认合并后仍能分别检出各类原缺陷、失败时能定位；不能以“合并后的大例在旧版本失败一次”代替逐类确认。
5. 记录来源仓库、revision、原测试位置和缩减／组合关系。复制或改编外部测试时检查其许可证与署名要求，按仓库约定保留声明；不要假定测试集与 grammar 同许可证。
6. 修复后重跑持久化回归及相同的选定外部语料，检查原差异和新增退化。相关语法范围变化可以扩展语料，但不能缩小范围掩盖失败。

必要的基础契约和结构测试仍需保留；没有发现缺陷就如实报告，不为了数量复制通过的外部样例，也不制造失败。普通回归应接入本地和 CI 测试，尽量不依赖联网或官方工具。值得重复运行的对照可保留小型脚本或显式入口；不整批提交上游测试集、临时下载或运行日志。

## 可复查的结果

在 PR 或交付说明中保留实现与语料版本、可复现命令或脚本、实际范围与跳过项、差异分类、回归和复查结论，不为保存本次验证过程默认新增仓库文档。长期维护确需复用的验证入口、更新方法和已知语法限制，放入现有相关文档或测试旁的简短说明；来源与许可证仍按仓库约定持久化。

外部脚本若负责非平凡提取或筛选，值得重复运行时保留可维护的脚本及入口；一次性分析则在交付说明中描述足以重建的步骤，不只给出失效的临时路径。区分官方测试任务、源码文件、提取片段及本仓库回归，不能用文件数或通过率推断完整语法覆盖。

确认的未解决语法缺陷须继续处理，或明确作为尚未完成的工作交付；工具或环境的限制如实说明。证据只覆盖本次实际验证的范围。
